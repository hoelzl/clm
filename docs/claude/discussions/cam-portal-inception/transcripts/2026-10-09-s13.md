## Owner


The current clm version was written mostly to fulfil the tasks I needed to do, when I myself was fully responsible for creating the material for the courses, distributing it to students, and running the live-sessions. However, as CAM is growing, we have more and more concurrent courses with different trainers, and some of the administrative work done by a secretary, and other jobs that trainers should be able to handle themselves. This includes some tasks that were now mostly done in an ad-hoc fashion (like setting up Memberspot groups and courses, messaging the participants about their memberspot accounts, etc.) that should now be done in a more standardized manner using tools, as well as rethinking how some of the other tasks might be done (e.g., distributing the courses to students via release streams seems to be sound as an idea, but the current implementation is tied to having the full repository available and relies essentially on a single git checkout to run). Furthermore, we would need to provide different levels of access to various participants, e.g., the back-office should have access to participant data but not the course materials, trainers should have access to the output repositories of their courses and the participant data of the courses they teach but not to the sources of the slide decks (only the outputs, without the speaker notes), and they should be able to release the material for the courses they teach; course creators should have access to the sources of the slide decks, but they don't need access to student data or the ability to release courses (unless they are also trainer for a course), etc.
I'm not sure whether we should try to extend and restructure clm to become a single system (probably with multiple modules) that can serve all these tasks, or whether we should try to create different systems sharing a common library, but specialized for different users. I'd like to discuss this topic with you and start to develop an inception document for the new system(s). Let's discuss this. Perhaps it might help if you interviewed me about the domain and the planned system. I probably don't have great answers for everything, but it might help us understand the task ahead and the domain.
