## Agent

I’ve resumed the thread from S3 and read the S2 argument. **I recommend removing the legacy top-level model-invoking verbs, while retaining `sync-at-rev` as a model-free historical-deck export.**

The settled boundary remains: CLM produces evidence and framed tasks; the driving agent supplies judgment; embedded LLM execution is available only through explicit `autopilot`. Port/compare framing, the separate `compare-accept` report path, and the model-free MCP conversion are already settled.

### Proposed decision

| Verb | Treatment |
|---|---|
| `harvest port` | Remove. Replacement: `task --kind port` → `accept`. |
| `harvest compare` | Remove. Replacement: `task --kind compare` → `compare-accept`. |
| `harvest backfill` | Remove. Document the agent-driven loop instead. |
| `harvest compare-from-inventory` | Remove its top-level embedded-model composition too; otherwise it leaves the same loophole. |
| `harvest sync-at-rev` | Retain as an explicit artifact-producing write: export the historical deck, without embedded merge/polish. Remove its model-related options and document the changed contract. |
| `harvest compare-report` | Retain as deterministic rendering; ensure its imports do not transitively load the LLM client. |

An “autopilot-marked” shim that still executes a model under `harvest port` would contradict #960’s acceptance criterion. A shim that merely exits with migration guidance would satisfy it, but I lean toward outright removal with clear migration documentation. Legacy execution that we preserve should be reachable **through `harvest autopilot` itself**.

### One important detail about `sync-at-rev`

The current implementation exports via `git show` and then invokes the full embedded-model pipeline. Removing that second step means its output contains **only narration already present at that revision**, not narration newly recovered from the recording.

The documented backfill loop therefore needs to make the recovery step explicit:

1. `identify-rev --json` → agent selects a revision.
2. Export the historical deck with the model-free `sync-at-rev`.
3. On that exported deck, use `report` → curate `task` → `accept` to recover recording narration, when needed.
4. On the current deck, use `task --kind port` with the historical deck as source → `accept`.
5. Verify; optionally frame and accept a comparison report.

I’ll also check historical companion-file handling so the exported artifact is usable by the current task/accept machinery.

The alignment MCP mirror remains deferred; it needn’t block this retirement. The private-import guard will be an explicit check before pushing, and GitHub bodies will use `--body-file`.

**Do you agree with removing the legacy verbs outright and keeping `sync-at-rev` as export-only, with narration recovery handled by the existing agent loop?**
