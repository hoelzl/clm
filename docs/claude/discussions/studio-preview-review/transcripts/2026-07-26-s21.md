## Verdict on #704

**No new bypasses found; nothing blocks merge.** More importantly, the round-2 fixes are the *right kind* of fix, not patches on patches:

- The **reject-only invariant** on `attribute_filter` addresses the root of the round-2 XSS (nh3 validates the incoming value, writes whatever the filter returns — so rewriting *is* escaping the check). It's stated as an invariant with a test that used to assert the opposite.
- The **prefix×scheme cross-product property test** replaced case-by-case whack-a-mole, and immediately caught a real desync in the other direction (`<tab>blob:`).
- The filter's normalization strips a **superset** of what the browser strips — the safe direction: it can only over-refuse, never under-refuse.
- Sanitize-after-deprefix, `body` echoing the request instead of the expansion, fail-closed without nh3, gate tested from *both* sides of the contract (predicate under `node` + the real service payload) — all correct.

## The root-cause question: why did two rounds find critical bugs?

Three systemic causes, in order of leverage:

### 1. No defense in depth — a sanitizer miss is immediately fatal (the real design mistake)

The Studio page holds a **non-expiring bearer token in `localStorage`**, and the app sets **no Content-Security-Policy anywhere** (verified: the only middleware is CORS; the D4 guards cover DNS-rebinding and CSRF, not content injection). That is what turns every sanitizer imperfection into token theft. The round-2 `javascript:` URL was one tap away from exfiltrating it.

**Fix the class, not the instance:** add a security-headers middleware:
```
Content-Security-Policy: default-src 'self'; script-src 'self';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: https:;
  connect-src 'self'; object-src 'none'; base-uri 'none';
  frame-ancestors 'none'; form-action 'none'
```
This is cheap here: `app.js` is already external (no inline scripts/handlers), only styles need `unsafe-inline` (which the sanitizer already governs). With `script-src 'self'`, **every bug found in rounds 1–2 becomes unexploitable for script execution even at its worst**, and `connect-src 'self'` closes the exfil channel. This converts "sanitizer must be perfect" into "sanitizer bugs are defacement bugs." Longer-term, the token itself wants a lifecycle (short-lived pairing + refresh), but CSP gets you most of the protection today.

### 2. Every confirmed bug lived in the hand-rolled layer over nh3 — so shrink that layer

nh3's core allowlist held through both rounds; all three round-1 bypasses and the round-2 XSS were in *bespoke* policy (URL normalization, authority-relative refusal, `class`, CSS regex). The durable lesson: **policy you don't have can't be bypassed.** Two concrete reductions:

- **Delete the `data:` rule entirely — serve the logo as an asset URL.** The `data:` confinement is the single most complex hand-rolled rule (and the site of round-1 bug #1, plus most of the property-test matrix). The logo is a `data:` URI because *notebooks* need self-contained HTML; the preview endpoint doesn't. Rewriting `<img src="data:…">` → `<img src="/api/studio/asset/…">` *before* sanitizing (order preserved) lets `data` leave `ALLOWED_URL_SCHEMES` completely. Worth an issue even if not done in #704.
- The CSS property filter is acceptable as-is (tight allowlist, reject-only, residual risk honestly documented as visual-only) — but if it ever has to grow, switch to `tinycss2` rather than extending the regex. Parse, don't pattern-match.

### 3. The process bug: "wired" claims without an executing test

The original sin was the dead tier-2 path surviving a phase sign-off, plus docstrings that overclaimed ("can only ever be more restrictive"). #704 institutionalizes the correct pattern — named predicate executed under `node`, contract test against the real service payload, consumer executed, wiring pinned by an admittedly-static check. I'd promote that pattern from a design-doc correction into a **standing rule in the Studio's testing docs / AGENTS.md**: a build record claiming a path is wired must cite the test that executes it, and security-relevant docstring claims ("X can never happen") must cite the test that proves it.

## Secondary observations
