## #1140: what I found in CppCourses
- **The published repo is the build output directory itself.** `output/shared/cpp-for-programmers-de` has `shared/…-de` as its origin. Its working tree already differs from what students have in 52 Code-Along files. So "the destination" and "the current build" are already two different things.
- **The channel needs its own clone of the same remote.** A channel can't use the output directory as its working tree, because `clm build` rewrites it. Students keep their remote, so nothing changes for them.
- **The old `clm git push` on `shared` must be cut off.** Otherwise a single push overwrites the frozen state with the unfrozen build.
- **The issue's open question is answered:** `source-target="shared"` is supported. With `lang="de"`, paths are re-rooted to `Folien/…` and `code/…`, which matches the repo layout.
- **`topic_digest` is written but never read anywhere**, so an adopted record only has to use the same format.
- **862 of the 2,438 files belong to no topic.** They're the C++ IDE export under `code/`: `external`, `completed` and `starter_kits`.

## Proposal
`clm release adopt SPEC --channel X (TOPIC… | --section … | --all-present)` freezes topics as they exist in the channel's clone. It never changes content: the only files it writes are the frozen manifest and the ledger. For every file it reports whether it's the same as the build, differs, or is missing. That report is also the "what would a rebuild change for students" view the issue asks for.

## Decisions I need from you (my recommendation in bold)
1. **A separate `adopt` command**, rather than a `sync --adopt` flag.
2. **When a file differs from the build:** **adopt anyway**, with the digest computed from what students have, and flag it as differing.
3. **When a file is missing** (usually a renumbered deck): **refuse that topic.** An opt-in `--deliver-missing` would copy only the missing files and never overwrite anything.
4. **The `code/` tree:** **freeze it and don't make it evergreen**, because students edit `starter_kits` in place.
   - The catch: new exercises would then reach students only through `--refreeze-skeleton`.
   - The proper fix is to give each `code/completed/<topic>` an owning topic in the export. That's a separate, larger issue.
5. **No default topic selection.** Adopting freezes a topic for good, so you must name the topics, a section, or `--all-present`.
6. **Guard the old push path:** **`clm git push` on an output target refuses** when a channel's clone has the same origin. An override flag lets you push anyway.
7. **Adopted records get `source_commit = published:<HEAD sha>`**, because the real source commit is unknown.
